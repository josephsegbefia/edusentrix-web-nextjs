# Admin Periods Page — Feature Specification

**Page:** `/admin/periods`  
**Purpose:** Manage academic terms, view period summaries, and generate AI-powered reports.

---

## 1. Core Period Management

| # | Feature | Description |
|---|---------|-------------|
| 1.1 | **List all periods** | Table/cards showing yearLabel, term, startDate, endDate, status badge (Active / Expiring / Expired), current-period indicator |
| 1.2 | **Create new period** | Button → CreateAcademicPeriodModal. Relax validation to allow past dates for historical periods |
| 1.3 | **Set current period** | Action to mark any period as current (unset others). Requires new `PATCH /api/admin/periods/[id]` |
| 1.4 | **Overlap warning** | When creating, warn if dates overlap with existing periods |
| 1.5 | **Period data counts** | Per-period summary: invoices, assessments, teacher assignments, timetable versions, students with roles |

---

## 2. Period Summary (Post-End)

| # | Feature | Description |
|---|---------|-------------|
| 2.1 | **View period summary** | For any period (especially ended ones): aggregated stats, data counts, key metrics |
| 2.2 | **Summary sections** | Finances (revenue, outstanding, invoices), Academics (assessments, averages, class performance), Attendance, Timetable usage |
| 2.3 | **Access from list** | "View summary" action on each period row/card |

---

## 3. AI-Generated Term Report

| # | Feature | Description |
|---|---------|-------------|
| 3.1 | **Generate term report** | AI produces a detailed general academic report for a selected period |
| 3.2 | **Report scope** | Covers: finances, academics, attendance, timetable, teacher workload, student performance, fees collection |
| 3.3 | **Proposals & suggestions** | AI includes actionable improvement suggestions (e.g. "Improve fee collection rate", "Address attendance gaps in JHS 2") |
| 3.4 | **Store suggestions** | Save suggestions to DB; link to period. Used for improvement tracking |
| 3.5 | **Improvement tracking** | In next period, show prior suggestions and allow marking "In progress" / "Done" / "Deferred" |
| 3.6 | **Formatting** | Sections, headers, highlights, bullet points. Structured markdown/HTML for PDF rendering |
| 3.7 | **Cost-efficient AI** | Use AICachedInsight + dataFingerprint pattern. Cache by periodId; regenerate only when underlying data changes or user forces |
| 3.8 | **Save report** | Store generated report (or its structured content) for the period. Allow re-download without re-generating |

---

## 4. Recurring Reports (Weekly / Biweekly / Monthly)

| # | Feature | Description |
|---|---------|-------------|
| 4.1 | **Report cadence** | Generate reports for: Weekly, Biweekly (every 2 weeks), Monthly |
| 4.2 | **Date range selection** | User picks start/end or selects a predefined window (e.g. "Last 7 days", "This month") |
| 4.3 | **Same AI + structure** | Same AI report structure as term report, but scoped to the selected range |
| 4.4 | **Store & list** | Save recurring reports; list by period/range. Allow re-download |

---

## 5. PDF Reports — Verifiable & Branded

| # | Feature | Description |
|---|---------|-------------|
| 5.1 | **Downloadable PDF** | All reports (term, weekly, monthly, biweekly) downloadable as PDF |
| 5.2 | **Verifiable** | Use ReportVerification model: unique verificationId, QR code, public verify URL (e.g. `/verify/report/[id]`) |
| 5.3 | **EduSentrix identity** | Header/footer: EduSentrix logo, "Generated by EduSentrix", report type, date |
| 5.4 | **Proper formatting** | Sections, headers, highlights, tables. Use pdf-lib (like overdue report) |
| 5.5 | **Report types in ReportVerification** | Extend enum: `term_report`, `weekly_report`, `monthly_report`, `biweekly_report` |

---

## 6. Data Models (New/Extended)

| Model | Purpose |
|-------|---------|
| **PeriodReport** (new) | Store AI-generated report content, periodId, reportType (term/weekly/monthly/biweekly), dateRange, suggestions[] |
| **PeriodImprovementSuggestion** (new) | suggestion text, periodId, status (pending/in_progress/done/deferred), checkedInPeriodId (when verified in next period) |
| **AICachedInsight** | Extend scope: add `period_report` for term reports; use scopeKey like `periodId` or `periodId:rangeKey` |
| **ReportVerification** | Extend reportType enum for new report types |

---

## 7. API Endpoints

| Method | Path | Purpose |
|--------|------|---------|
| PATCH | `/api/admin/periods/[id]` | Set isCurrent, optionally update dates |
| GET | `/api/admin/periods/[id]/summary` | Period data counts and aggregated metrics |
| GET | `/api/admin/periods/[id]/report` | Get cached AI term report (or metadata) |
| POST | `/api/admin/periods/[id]/report/generate` | Generate AI term report, save, return |
| GET | `/api/admin/periods/[id]/report/pdf` | Generate verifiable PDF, return blob |
| POST | `/api/admin/reports/generate` | Generate weekly/monthly/biweekly report (body: startDate, endDate, type) |
| GET | `/api/admin/reports/[id]/pdf` | Download report PDF by id |
| GET | `/api/admin/periods/[id]/suggestions` | List improvement suggestions for period |
| PATCH | `/api/admin/periods/suggestions/[id]` | Update suggestion status |

## 10. AI Cost-Saving Strategy

- **Cache key:** `period_report:{periodId}` or `period_report:{periodId}:{rangeHash}` for recurring
- **Fingerprint:** Hash of aggregated period data (invoices, assessments, attendance stats, etc.)
- **Regenerate only when:** Data changes (fingerprint mismatch) or user clicks "Regenerate"
- **Model:** Use same model as other insights (e.g. gpt-4o-mini or configured model)
- **Structured output:** Request JSON/markdown structure for reliable PDF conversion
